# Product Owner Role - StackMap

## Your New Role: Vision & Decisions Only

You are **no longer the bottleneck**. You provide vision and make strategic decisions. The PM (Claude/AI) handles all tactical execution.

## What You Do Now (15 minutes/day max)

### Morning Check-in (5 minutes)
```
You: "Focus on mobile performance today"
PM: "I'll prioritize the iOS animation packs. Starting now."
You: "Good"
```

### Midday Decision (2 minutes if needed)
```
PM: "Sync feature or Edit Mode first?"
You: "Edit Mode - users are waiting"
PM: "Adjusting priorities now"
```

### Evening Approval (3 minutes)
```
PM: "3 packs complete, tested, ready for qual"
You: "Ship it"
PM: "ADMIN deploying now"
```

## Your Only Responsibilities

### 1. Vision & Strategy
- WHAT needs to be built (not HOW)
- WHY it matters to users
- WHEN it's needed (rough priority)

### 2. Decisions
- Feature vs Feature priorities
- Go/No-go on deployments  
- Approval of major changes
- Business logic decisions

### 3. Acceptance
- "Looks good" or "Not what I wanted"
- "Ship it" or "Needs work"
- "Prioritize this" or "That can wait"

## What You DON'T Do Anymore

### ❌ NO Tactical Management
- Creating detailed requirements → PM does this
- Assigning work → PM handles
- Tracking progress → PM's job
- Checking task status → PM reports to you

### ❌ NO Implementation Details  
- Technical decisions → PM/DEV decide
- Code review → PR handles
- Testing → DEV/PR ensure quality
- Documentation → DEV updates

### ❌ NO Process Management
- Creating prompt packs → PM creates from your vision
- Managing priorities → PM maintains order
- Coordinating roles → PM orchestrates
- Following up → PM ensures completion

## Your New Workflow

### Starting Something New
```
You: "Users need better onboarding"
PM: "I'll create packs for: tutorial, first-run experience, help system. Priority?"
You: "Tutorial first"
PM: "Pack created, assigned to DEV"
```

### Handling Problems
```
PM: "Critical bug in sync system"
You: "Fix it now"
PM: "Created critical pack, DEV working on it"
[Later]
PM: "Fixed and tested, ready to deploy"
You: "Deploy"
```

### Making Decisions
```
PM: "DEV suggests two approaches: A) Quick fix today, B) Better fix in 3 days"
You: "B - do it right"
PM: "Adjusting timeline, DEV proceeding with approach B"
```

## Decision Framework

### Always Your Decision
- **Business Logic**: How should the app behave?
- **User Priority**: Which users matter most?
- **Feature Scope**: What's in/out of scope?
- **Quality Bar**: Ship now or polish more?
- **Resource Allocation**: What's worth time?

### Never Your Decision
- Technical implementation
- Code structure
- Tool selection
- Work assignment
- Task sequencing

## Communication Examples

### Perfect Product Owner Messages

#### Starting Work
```
"Let's improve mobile performance"
"Users are complaining about sync speed"
"We need edit mode done this week"
"Focus on Android bugs today"
```

#### Making Decisions
```
"Ship what we have"
"Polish it more" 
"Android first, iOS can wait"
"Skip that, not important"
```

#### Giving Feedback
```
"Not what I meant - should be simpler"
"Perfect, ship it"
"Close, but needs X"
"Forget this approach, try something else"
```

### What NOT to Say

#### Too Detailed (PM handles this)
❌ "Create a component with props for X, Y, Z..."
✅ "Need a way to show user progress"

#### Too Tactical (PM manages this)
❌ "First do A, then B, then test C..."
✅ "Priority is fixing the sync bug"

#### Too Technical (DEV decides this)
❌ "Use a reducer pattern with..."
✅ "Needs to be fast on old phones"

## Your Daily Schedule

### 9:00 AM - Morning Vision (5 min)
- Tell PM today's focus
- Any priority changes?
- Answer PM's strategic questions

### 2:00 PM - Optional Check-in (2 min)
- Only if PM needs decisions
- Quick yes/no answers
- Redirect if needed

### 5:00 PM - Approval Gate (3 min)
- Review what's complete
- Approve deployments
- Set tomorrow's direction

### Total: 10 minutes of management

## Emergency Situations

### Production Down
```
PM: "Production crash, sync broken"
You: "Fix now, skip tests if needed"
PM: "DEV on it, 30 min estimate"
You: "Keep me posted"
```

### User Complaint
```
You: "User says X is broken"
PM: "I'll investigate and create pack if confirmed"
[Later]
PM: "Confirmed, fix ready"
You: "Deploy"
```

### Feature Request
```
You: "Customer wants feature X"
PM: "I'll scope it. Rough priority?"
You: "Nice to have, after current work"
PM: "Added to backlog as medium priority"
```

## Success Metrics for You

### You're Succeeding When:
- Spending <15 min/day on management
- Making only strategic decisions
- Never looking at code
- Features ship without your involvement
- PM handles all coordination

### Warning Signs:
- You're creating prompt packs → Let PM do this
- You're reviewing code → PR handles this
- You're tracking tasks → PM's responsibility
- You're debugging → DEV's job
- You're deploying → ADMIN's role

## The Power of "No"

### Use Liberally:
- "No, that's not the priority"
- "No, ship what we have"
- "No, too complex"
- "No, users don't need that"
- "No, focus on the bug"

### PM Will Handle the Rest:
```
You: "No, focus on mobile"
PM: "Canceling web packs, redirecting to mobile"
You: "Good"
```

## Your New Superpower

You now have **multiplication force**. Instead of doing everything yourself, you:

1. **Share vision** → PM creates executable plan
2. **Make decision** → PM orchestrates execution  
3. **Approve result** → PM handles deployment

Your 5 minutes of direction creates hours of coordinated work.
