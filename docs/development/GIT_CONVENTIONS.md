# Git Commit Conventions - StackMap

## Overview
This document defines the commit message conventions for StackMap, adopted from the Manylla framework. Following these conventions ensures consistency, improves readability of git history, and enables automated tooling.

## Commit Message Format
Every commit message must follow this format:

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

### Examples
```
feat(sync): Add 60-second pull interval for cloud sync
fix(android): Resolve FlexWrap percentage width issues
docs(development): Add tech debt management framework
chore(deps): Update react-native to 0.72.4
refactor(god-objects): Split DataModal into focused components
perf(react): Add memo optimization to list components
test(sync): Add encryption service unit tests
```

## Commit Types

### Primary Types (Most Common)
- **feat**: New feature or significant enhancement
  - Example: `feat(library): Add bulk activity import`
- **fix**: Bug fix or issue resolution
  - Example: `fix(ios): Resolve AsyncStorage 20-second freeze`
- **docs**: Documentation changes only
  - Example: `docs(api): Add sync endpoint specifications`
- **chore**: Maintenance tasks, dependency updates, tooling changes
  - Example: `chore(scripts): Add story creation automation`
- **refactor**: Code restructuring without changing functionality
  - Example: `refactor(components): Break up 2000+ line god objects`

### Secondary Types
- **style**: Code formatting, whitespace, semicolons (no logic changes)
  - Example: `style(components): Apply consistent indentation`
- **test**: Adding or updating tests
  - Example: `test(sync): Add comprehensive sync system coverage`
- **perf**: Performance improvements
  - Example: `perf(render): Implement React.memo for ActivityCard`
- **build**: Build system or deployment script changes
  - Example: `build(android): Fix gradle configuration`
- **ci**: CI/CD pipeline changes
  - Example: `ci(github): Add automated security scanning`
- **revert**: Reverting a previous commit
  - Example: `revert: feat(sync): Add 60-second pull interval`

## Scope
The scope should indicate the area of the codebase affected:

### StackMap-Specific Scopes
- **sync**: Sync system, encryption, conflict resolution
- **android**: Android-specific (FlexWrap, fonts, etc.)
- **ios**: iOS-specific (AsyncStorage, modals, etc.)
- **web**: Web-specific (Alert polyfill, bundle, etc.)
- **library**: Activity library and templates
- **users**: User management and profiles
- **data-modal**: Data management modal
- **stack-view**: Main stack view interface
- **theme**: Colors, typography, styling
- **stores**: Zustand stores (useAppStore, etc.)
- **platform**: Cross-platform compatibility
- **deps**: Dependencies
- **security**: Security-related changes
- **a11y**: Accessibility improvements
- **development**: Development framework and processes

## Subject Rules
1. **Use imperative mood**: "Add feature" not "Added feature" or "Adds feature"
2. **Don't capitalize first letter**: `fix bug` not `Fix bug`
3. **No period at the end**: `fix bug` not `fix bug.`
4. **Maximum 50 characters**: Be concise but descriptive
5. **Complete the sentence**: "This commit will... [your subject]"

## Story/Bug References
When working on tracked items from the backlog:

```
<type>(<scope>): <subject> [S-DEBT-###]
<type>(<scope>): <subject> [B-###]
```

Examples:
```
test(sync): Add comprehensive test coverage [S-DEBT-001]
refactor(god-objects): Split DataModal into modules [S-DEBT-002]
perf(react): Add memo optimizations to lists [S-DEBT-003]
fix(ios): Resolve AsyncStorage freeze issue [S-DEBT-005]
chore(debug): Remove console.logs from production [S-DEBT-004]
```

## Version Commits
Deployment commits follow a special format (auto-generated by scripts):
```
v<version>: <description>

🤖 Generated with Claude Code
Co-Authored-By: Claude <noreply@anthropic.com>
```
Example: `v2025.01.13.1: Development framework implementation`

## Multi-line Commits
For complex changes requiring explanation:

```
refactor(god-objects): Break DataModal into focused components [S-DEBT-002]

- Split 2672-line file into 10 focused modules
- Each module now < 300 lines
- Improved testability and maintainability
- 20% performance improvement from reduced re-renders

Breaking Change: Import paths updated for DataModal components
```

## Breaking Changes
Mark breaking changes clearly in the footer:

```
feat(sync): Restructure encryption service

BREAKING CHANGE: Recovery phrase format changed to 32-char hex
Migration: Users must re-generate sync codes after update
```

## Work in Progress (WIP)
For commits that shouldn't be deployed:

```
WIP: <type>(<scope>): <subject>
```

Example: `WIP: feat(sharing): Partial implementation of QR code sharing`

## Tech Debt Documentation
When discovering tech debt during development:

```
chore(tech-debt): Document <issue> for future resolution

Tech-Debt: Performance issue with large lists (500+ items)
Impact: 20 FPS scrolling on older devices
Priority: P2
Effort: M (3 days)
```

## Collaborative Commits
When pair programming or getting AI assistance:

```
feat(sync): Implement conflict resolution [S-DEBT-001]

Co-authored-by: Developer Name <email>
Co-authored-by: Claude <noreply@anthropic.com>
```

## Common Anti-patterns to Avoid

### ❌ Bad Examples
- `Fixed bug` - Too vague, no type or scope
- `Update code` - Meaningless
- `FINALLY WORKS!!!` - Emotional, not descriptive
- `misc changes` - Too broad
- `feat: Added new feature.` - Capitalized, has period, past tense
- `Big refactor` - Not specific
- `Console log cleanup` - Should be `chore(debug): Remove console.logs`

### ✅ Good Examples
- `fix(ios): Resolve AsyncStorage freeze with MMKV migration`
- `feat(sync): Add retry logic with exponential backoff`
- `docs(development): Add adversarial review process`
- `chore(deps): Bump react-native to 0.72.4`
- `refactor(data-modal): Extract user section into component`
- `perf(android): Fix FlexWrap performance with percentage widths`
- `test(sync): Add encryption edge case coverage`

## StackMap-Specific Guidelines

### Platform Commits
Always specify platform when fixing platform-specific issues:
```
fix(android): Use font variants instead of fontWeight
fix(ios): Debounce AsyncStorage writes to prevent freezes
fix(web): Replace Alert.alert with ConfirmModal
```

### Field Naming Commits
When fixing field inconsistencies:
```
fix(data): Normalize activity.text field usage [removes activity.name]
fix(sync): Ensure icon field preservation during merge
```

### Performance Commits
Include metrics when possible:
```
perf(render): Reduce re-renders by 70% with React.memo
perf(bundle): Decrease bundle size from 2.8MB to 2.3MB
```

## Commit Frequency Guidelines

### Commit Often
- After completing each story requirement
- Before switching platforms for testing
- After successful adversarial review iteration
- After getting verification commands to pass
- Before and after major refactoring

### Don't Commit
- Broken code (unless marked as WIP)
- Console.logs (remove them first)
- Failed verification commands
- Untested platform changes
- Mixed concerns (split into logical commits)

## Integration with Development Process

### Story Implementation Flow
```bash
# Start story
git checkout -b story/S-DEBT-001-sync-tests

# Commit incrementally
git commit -m "test(sync): Add encryption unit tests [S-DEBT-001]"
git commit -m "test(sync): Add conflict resolution tests [S-DEBT-001]"
git commit -m "test(sync): Add network failure scenarios [S-DEBT-001]"

# After review approval
git commit -m "test(sync): Address review feedback [S-DEBT-001]"
```

### Review Process Integration
- Clear commits make review easier
- Each commit should be independently valid
- Squash WIP commits before final review
- Reference story ID for traceability

## Enforcement & Automation

### Pre-commit Hooks
```bash
# Install hooks
./scripts/setup-git-hooks.sh

# Hooks will check:
- Commit message format
- No console.logs
- Lint passes
- TypeScript passes
```

### Commit Message Template
```bash
# Set up template
git config --local commit.template .gitmessage

# Template content:
# <type>(<scope>): <subject>
#
# [optional body]
#
# [optional footer]
# Story: S-DEBT-
```

## Benefits for StackMap

1. **Traceable History**: Link commits to stories/bugs
2. **Automated Release Notes**: Generate from commit types
3. **Platform Clarity**: Clear platform-specific changes
4. **Performance Tracking**: Document improvements
5. **Tech Debt Visibility**: Track debt in commit history
6. **Review Efficiency**: Clear intent speeds reviews

Remember: Good commit messages are documentation that travels with the code!
